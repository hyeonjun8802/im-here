## 2. 구현 세부

### 식생

- `src/rooftopBotany.js`: 실제 화단 좌표(-13, 11/14.2/17.4)에서 생성되는 작물, 덩굴·자연 수형, 열매.
- `public/assets/materials/botany/leaf_veined.png`: 자체 생성한 알파 채널 및 잎맥 텍스처.
- `src/premiumEnvironmentV130.js`: 기존 풍력 반응 잎도 텍스처를 활용하도록 형상·UV 수정.
- `src/artDirection.js`: 저폴리 식물 GLB 8개를 배치 리스트에서 제외(파일과 기존 시설 GLB는 보존).
- `src/world.js`: 기존 화단 나뭇잎 막대 메시 제거, 식생 생성기를 기존 화단에 연결.
- 식생 잎/줄기/나무 줄기/작은 열매는 각각 공유 지오메트리와 `InstancedMesh`로 배치.

### 행동/이동

- `src/roofNavigation.js`: 단일 옥상의 실제 지오메트리 크기에 맞춘 정적 충돌 도형. 동적 리지드바디 엔진이 아니라 **캐릭터용 kinematic 네비게이션·충돌**입니다.
- `src/survivorLife.js`: 접근 단계에서 충돌 없는 경로 생성, 이동 중 관통 방지, 접근 불가 시 중단. 의자 착석은 의도적인 별도 전환으로 보존.
- 방해받던 도시 관찰 목표 지점은 화단 내부 `[-17,17]`에서 이동 가능한 `[-4,18]`로 수정.
- 음식 소비는 `simulation.js`가 여전히 유일한 자원 변경 주체입니다. 단, 실제 식사는 이동 후 시작하는 애니메이션으로 표현됩니다.
- `src/characterMotionPlanV190.js` 및 `src/beardedSurvivorV190.js`: 실제 GLB 관절에 식량 메시를 연결하고 반복 손→입 모션 추가.

### 하늘

- `src/world.js`: 네 장의 낮·황혼·폭풍·밤 사진 실린더를 중단하고 하나의 방향 기반 shader sky sphere로 통일.
- `public/assets/materials/botany/cloud_volume.png`: 시간에 따라 천천히 이동하는 절차적 구름의 단일 노이즈 필드.
- 천체 셰이더 `celestialSky.js`와 실제 서울 기준 태양·달 계산은 유지. 기상 시스템에서 기존 비/폭풍 효과는 계속 작동합니다.

## 3. 검증한 것

- Node 자동 테스트 **174/174 통과** (기존 169개 + 신규 5개). 검사는 기존 기능과 새로운 13종 콜라이더·충돌 없는 구간·모든 주요 행동 지점 간 경로·손→입 모션·하늘 중첩 제거를 포함.
- 모델 리소스 **83/83** 존재 확인.
- 독립 실행형 JS/CSS/3D 리소스 빌드 생성 및 HTTP 응답 검증.
- 기존 `simulation.js`는 원본 그대로 유지.

## 4. 확인하지 못한 것 — 출시 승인 조건

- **실제 브라우저 WebGL 캡처 및 육안 비교**: Linux Chromium에서 GPU/WebGL 초기화 또는 촬영 시간 초과. 성공으로 표시하지 않습니다.
- **실기기 FPS 및 식생 투명 경계의 픽셀 수준 검증**: 미수행.
- **모든 동적 GLB 오브젝트의 충돌**: 이번 버전에서는 고정 주요 시설만 충돌 처리했습니다. 모든 소품의 크기 변화를 반영하는 동적 충돌/리지드바디 물리 엔진은 아직 미구현입니다.
- **기존 GLB 캐릭터의 손→입 실제 접촉 정확도**: 관절 수치 기반 모션 구현까지 검증. 최종 피부/손 위치는 Mac WebGL 캡처로 비교 필요.

## 5. 실기기 화면 확인

1. `RUN_STANDALONE_MAC.command`를 실행해 일반 게임을 확인합니다.
2. 화면 오른쪽 `기상 시스템 시연`에서 일몰/밤/보름달을 확인합니다.
3. 아래 메뉴 `식사`를 눌러 손에서 입으로 이동하는 식량 소품을 확인합니다(식량 1개 소비).
4. `CAPTURE_GAME_MAC.command`는 별도 사용자 Chrome에서 캡처를 시도합니다. 이 스크립트는 실제 Mac에서 확인하지 못했습니다.
