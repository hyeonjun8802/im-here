# AFTERDAY — 콘셉트 고정 계약 (Codex 필독)

> 상태: **핵심 디자인 규칙 / v0.5.1**. 본 문서는 `docs/AFTERDAY_GAME_DESIGN.md`, `docs/AFTERDAY_ART_DESIGN.md`, `docs/visual-reference/rooftop_target.png`, `docs/visual-reference/weather_target.png`와 함께 읽는다. 아래 강제 금지 조항은 GitHub 모델 재사용 편의보다 우선한다.

## 1. 게임의 핵심 정체성 (변경 금지)

**AFTERDAY = 폐허가 된 서울을 내려다보는 옥상 한 곳에서, 성인 생존자 한 명이 실제 날짜에 맞춰 생활하고 재난을 견디는 3D 관찰형 다마고치.**

- 게임 경험: 재난·생존 **70%**, 일상 관찰 **25%**, 긴급한 물자 고갈 시 탐험 **5%**.
- 플레이어 역할: 도시 개발자가 아닌 *생존자의 환경을 정비하고 위험에 개입하는 보호자*.
- 한 개 옥상만 플레이 공간; 도시 외곽은 **3D로 존재하지만 배경 레이어**. SimCity 지형 배치/도로 확장/도시경영 기능 구현 금지.
- 전투·군대·스킨 상점·경험치·자동차 운전·주택 분양·상업 건설·레벨 업·꾸미기 경제 금지.
- 비와 폭풍이 예쁘게 보이는 데 그치지 않고, 생존자의 대피·자원·시설 내구도·복구 행동과 연결되어야 한다.
- **기본 현실 4시간 = 게임 하루(24시간)**. 2×/4× 버튼은 활성 플레이 중 추가 가속. 시간·날짜 시연은 생존 데이터를 변경하지 않으며, 서버 없는 MVP는 시계 조작 방지 한계를 명시.


## 1-A. 최종 공간 배치 규칙 — 주인공 옥상 1개 (최우선)

- 화면의 **유일한 전경 옥상**은 주인공이 살고 있는 빌딩의 루프탑 1개이다. 건물 아래 외벽과 측면은 보여도 옆 건물의 옥상이나 이웃 캠프가 보이도록 배치하지 않는다.
- 주인공 옥상 주변은 열린 공중 공간이다. 난간 밖으로 손을 뻗으면 바로 낭떠러지와 멀리 있는 도시 풍경이 보인다. **옥상과 옥상 사이를 이어 붙이는 구조/보행로/공중다리/이웃 테라스/추가 설치용 부지는 전면 금지**한다.
- 다른 건물은 멀리 떨어진 서울의 폐허 원경으로 배치한다. 건물은 실제 3D GLB이되 주인공 옥상과 시각적으로 합쳐지지 않도록 거리·화각·안개·실루엣을 관리한다.
- 코드 기준: `src/spatialLayout.js`의 `heroRoofCount = 1`, `clearZoneRadius = 140`, `cityMinRadius = 166`, `cityMaxRadius = 875`. 수치는 게임 월드 단위이며 실제 미터를 의미하지 않는다.
- 카메라 360° 모든 방향에서 최소 140유닛 반경에는 다른 건물을 절대로 생성하지 않는다. 데브리·도로·버려진 차도 원경으로 보낸다.
- 장면 구도의 1순위는 **작은 따뜻한 단독 옥상 vs 광활하고 차가운 폐허 서울**의 대비이다. 가까운 옥상이 늘어나 도시 마을처럼 보이면 실패.
- 폭우·폭염·낙뢰·토네이도 등 모든 날씨에 동일한 건물 배치가 유지되어야 한다. 날씨 변경은 구조물 위치를 바꾸는 것이 아니다.

## 3. 사용 가능한 GitHub 자산과 런타임 기준

`src/artDirection.js`가 실행에 실제 적용되는 화이트리스트를 포함한다.

- `CITY_MODELS`: 서울의 아파트·업무 빌딩·산업 건물에 가까운 형태의 실제 GLB만 원경에 재사용.
- `ROOFTOP_PROPS`: 수리 가능하고 생존에 실용적인 옥상 시설만 재사용(벤치, 접이식 의자, 낡은 그릴, 태양광 패널, 화분, 폐기물통, 난간, 팔레트, 경량 창고 등).
- `ABANDONED_VEHICLES`: **버려진 고정형 차량**만 사용. 경찰차, 밝은 택시, 달리는 도로 교통/활성 산업 금지.
- `CITY_TINTS`, `PROP_TINT`, `VEHICLE_TINT`: 원본 GLB의 메시를 유지하되 차가운 회색·녹슨 색·바랜 올리브 계열로 조화. 재질은 오브젝트별로 복제하고 원본 아틀라스는 유지.
- 원본 manifest의 83종은 원본 인벤토리이자 사용 후보군이다. **83종을 모두 화면에 배치하라는 뜻이 아니다**. 3D 에셋 보유량보다 미학적 적합성 우선.

### 제외해야 할 예시

- 중국풍 사원·파고다·중국풍 아파트·시장, 테마파크, 놀이기구, 카지노, 화려한 쇼핑몰, 완전한 신도시 광장, 경찰 순찰 차량.
- 눈에 띄는 원색 신축 건물, 대량 움직이는 차량/시민, 캐주얼 형광 잔디·만화 캐릭터, UI가 화면을 덮는 도시 경영형 툴바.
- 예외: 작은 무너진 상점 구조물처럼 폐허 콘셉트에 맞게 **모델 자체를 실제로 재작업한 경우**에만 아트 리뷰 후 허용. 단순 색 필터만으로 복잡한 문화권별 건축 형태가 서울형 건물로 변하는 것은 아니다.

## 4. 3D 아트 방향 — 화면 하나의 규칙

**Stylized Cinematic Realism.** 중간 톤의 콘크리트, 습기에 녹슨 금속, 빛바랜 올리브 천막, 손때 묻은 목재, 과하지 않은 이끼, 따뜻한 주황색 화롯불. 도시 원경은 차갑고 거대하며 텅 비어 있고, 옥상만 작고 사람이 유지하는 따뜻한 실용 공간.

- 360도 카메라에서 전후좌우가 같은 3D 월드로 존재해야 한다. 배경 스크린샷을 사각 평면에 붙여 3D 완성이라고 하지 않는다.
- 낮→황혼→밤: 하늘, 태양 고도·색, 그림자, 안개, 모닥불 발광이 **연속 변화**. 계절과 정확한 태양 궤적의 상용 인증은 별도.
- 재난: 구름 집적 → 바람/나뭇잎 → 강우·번개/토네이도 → 젖은 바닥·대피 → 피해와 복구. 순간 색상 전환만으로 날씨 구현 완료 처리 금지.
- 시안은 **레퍼런스 이미지**이며 GLB가 아니다. 실제 모델링·PBR·LOD·애니메이션 작업이 필요.
- UI는 반투명한 적은 수의 정보 패널, 생존자의 핵심 상태와 위험 경보 위주. 도시 건설·상점·인벤토리 수백 칸 UI 금지.

## 5. 화면별 검수 조건 (Codex가 매번 적용)

실제 브라우저에서 *같은 월드*로 아래 장면을 촬영해 비교한다. 모든 조명·날씨 검사에서 **카메라 위치를 고정**해 화면 변화가 진짜 3D 환경 변화인지 판단한다.

| 샷 | 반드시 보여야 할 것 | 실패 판정 |
|---|---|---|
| 기본 낮 | 옥상 전체, 탱크·천막·생존자·도시 깊이 | 장난감 건물, 지나친 원색, 매끈한 박스 |
| 석양 | 도시의 차가움 vs 작은 화롯불의 따뜻함 | 단순 붉은 화면 덮기 |
| 밤 | 어두워도 실루엣·화로·생존자 식별 | 완전 검은 화면, 낮과 동일한 그림자 |
| 폭우 | 3D 빗줄기, 젖은 지면, 강풍, 피난 | 날씨 PNG 교체로만 표현 |
| 뇌우 | 실제 광원 반응, 위험 경고, 실내 대피 | 번개 정적 아이콘만 표시 |
| 토네이도 | 원경에서 접근, 바람·먼지·피해·대피 | 옥상 한가운데 과장된 회오리 오브젝트 |
| 360° 회전 | 모델 후면과 다른 도시 시야, 배치 일관성 | 배경 그림이 카메라를 따라 회전 |
| 모바일 | 햇빛·기상 표현 유지, 조작 가능, 30FPS 목표 | PC만 실행, UI가 월드를 가림 |

검수 시 모델별 `loaded GLB / fallback / missing` 건수를 기록한다. **대체 박스가 다수인 빌드를 완성품이라 선언하지 않는다.** 실제 GLB 다운로드 없이는 현재 소스 ZIP에서 다수 빌딩이 폴백 모델임을 명시한다.

## 6. 기존 코드 보호 / 수정 우선순위

- `src/simulation.js`의 게임 규칙·날짜·저장 포맷을 그래픽 수정 때문에 바꾸지 않는다.
- 기존 리소스 명세 `public/assets/manifest.json`, 원본 SHA, 저작권 고지를 보존한다.
- 현재 v0.5는 WebGL GPU 실기기 검증이 아직 없다. 렌더링 완료 또는 상용 최종 퀄리티라고 보고하지 않는다.
- 실제 구현 목표: ① GitHub GLB 다운로드·검증 ② **화면의 문화권·색감·소품 콘셉트 일관성** ③ 날씨/조명 실제 브라우저 촬영 ④ 캐릭터 리깅/애니메이션 ⑤ 모바일 FPS 측정.
- 임의의 대규모 리팩터링 금지; 문제를 일으키는 모델 선정·머티리얼·배치에 우선 집중.

## 7. Codex용 고정 지시문

> AFTERDAY의 승인된 3D 루프탑 생존 콘셉트와 참고 이미지를 절대적인 아트 기준으로 삼아라. `src/artDirection.js`의 허용 자산 목록을 우선 사용하되, GitHub 원본 리소스는 공급품일 뿐 SimCity 게임 디자인을 가져오지 마라. 도시 건설/주민 교통/전투/캐릭터 꾸미기 요소는 구현하지 마라. 2026-11-04 수정된 현실 4시간/게임 1일 가상 시계, 생존자 자율 행동, 날씨 및 재난 로직을 유지하면서 화면 품질을 개선하라. 모든 변경 후 실제 360도 회전 화면과 날씨별 샷을 비교해 시안 대비 차이를 보고하고, GLB가 로드되지 않은 장면을 완성이라고 말하지 마라.


## 2026-11-01 사용자 직접 수정 명령 — 배경 도시 시각적 배치 업데이트

옛 `src/spatialLayout.js`의 `clearZoneRadius=140`, `cityMinRadius=166`은 변경하지 않은 **원본 공간 계획 기준과 다른 시스템의 호환성 값**이다. 사용자의 최신 명령에 따라 실제 렌더되는 배경 도시에는 `src/cityComposition.js`의 `visualCityClearRadius=53`과 `src/cityContraction.js`/`src/cityInfillPlanV150.js`의 조밀한 필지 기반 배치가 우선 적용된다. 이 변경은 플레이어 옥상 옆에 다른 플레이 공간을 추가하지 않으며, 3D 건물은 주인공 옥상 아래에 배치된다. 건물 간 지오메트리 교차를 해결한 다음 월드에 배치한다. 원본 게임의 날짜/생존 규칙은 변경하지 않는다.
