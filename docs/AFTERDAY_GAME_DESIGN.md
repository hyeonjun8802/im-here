## 0. 반드시 고정할 제품 정체성 [확정]

AFTERDAY는 오픈월드 액션·전투·장식형 건설 시뮬레이션이 아니다. 작은 옥상 캠프 하나에서 캐릭터 한 명의 생존을 **관찰하고 필요할 때 개입하는** 지속형 다마고치다. 사용자가 가장 높은 가치를 둔 것은 **실제 날짜, 자연스러운 낮과 밤, 실제 3D 월드, 영화 같은 환경 재난, 작은 생존자의 자율적인 행동**이다.

- 콘텐츠 감각 비율: 재난 생존 **70%**, 자율적 일상 관찰 **25%**, 필수 물자 고갈·질병 등으로 발생하는 드문 긴급 탐험 **5%**. 이는 경험 구성 목표이지, 플레이 시간을 강제로 분할하는 로직이 아니다.
- **일반 전투 루프 금지.** 적을 잡아 경험치를 얻거나 전투력 성장시키지 않는다. 야생동물 침입은 보관함과 생존의 위협으로 표현하며 경고·차단·대피·쫓기로 대응한다.
- **꾸미기·외형 뽑기·의상 수집·스킨 상점·캐릭터 레벨 파밍 금지.** 그래픽 모델은 실용적인 생존 복장, 시설은 기능적 설비로 고정한다.
- **탐험 파밍 금지.** 식량·식수·의약품·수리 재료가 부족할 때만 옥상에서 아래층으로 내려가 제한된 위기 선택을 수행한다.
- **실제 3D 필수.** 시각 시안이나 화면 배경만 바꾸는 방식은 게임 제작의 완료 조건을 만족하지 못한다.
- 플레이어 장기 목표는 ‘강력해지기’가 아니라 **생존 일수 누적, 재난 대비 체계 확립, 회복 가능한 안정적 삶**이다.
- 관찰의 재미: 생존자는 사용자가 없어도 움직이고, 먹고, 마시고, 쉬고, 정비하며, 날씨와 위험에 대응한다.

## 1. 세계관과 감정 서사

### 1.1 세계

대규모 재난 이후 인구가 사라진 근미래의 서울을 모티프로 한 **가상의 폐허 도시**. 높은 옥상 위에는 작은 천막, 녹슨 물탱크, 모닥불, 몇 개의 식량 보관함과 덩굴이 있다. 수평선 너머에는 폐허가 된 밀집 도시와 먼 산, 통신탑의 실루엣이 펼쳐진다. 서울을 닮은 분위기는 유지하되 실제 브랜드·상표·공식 건물 외관을 그대로 복제해야 하는 과제는 아니다.

시각적 대비는 **압도적으로 차갑고 거대한 도시 / 작고 따뜻한 캠프**. 맑은 날에는 고요하며 비가 오거나 토네이도가 다가오면 같은 장소가 완전히 다른 세계처럼 변한다. 시각적 아름다움은 공포 연출과 병존하되, 플레이어는 대비와 수리로 불확실성을 통제할 수 있어야 한다.

### 1.2 내러티브 전달

- 장문의 컷신보다 옥상에서 벌어지는 작은 관찰: 저녁마다 모닥불 앞으로 돌아오는 캐릭터, 물이 부족해 물탱크를 열어보는 행동, 새벽에 비를 듣는 모습.
- 대화는 짧고 문맥에 맞게: "물이 얼마 남지 않았네", "바람이 커졌어. 로프를 묶어야겠다", "오늘도 살았다".
- 고정형 일지: 재난 시점, 선택, 남은 자원, 수리 이력, 특수 탐험 결과. LLM 없이도 완성되는 템플릿 우선.
- 부정적 선택 결과라도 무작위 즉사·회복 불가능한 장시간 방치 처벌은 피한다.

## 2. 타깃 사용자와 세션 설계 [제안]

- 모바일 Safari/Chrome 세로모드가 기본, 데스크톱 가로모드 대응.
- 짧은 방문(3~7분)을 상정하되, 3D 공간을 20~30분 관찰해도 자연스럽게 변화하도록 한다.
- 자주 접속하지 않아도 지속 가능. 접속 횟수를 늘리기 위해 억지 퀘스트·보상 팝업·광고 시청 유도를 넣지 않는다.
- 접근성: 자막, 저자극 번개 설정, 카메라 흔들림 감소, 재난 경고는 색상뿐 아니라 아이콘·문구로 함께 전달.

## 3. 실제 시간·날짜 계약 — 가장 중요한 기능 [확정]

**정식 플레이는 현실 시간 1초 = 게임 시간 1초(1:1)**. 게임 생성 시 `worldCreatedAtUtcMs`를 기록한다. `Asia/Seoul` 고정 타임존으로 세계의 달력 날짜·시간을 표시한다. 브라우저 프레임 수에 게임 시간을 의존하지 않는다.

| 개념 | 설명 | 필드 |
|---|---|---|
| 세계 생성 | 게임을 처음 만든 절대 UTC 시각 | `worldCreatedAtUtcMs` |
| 서버 기준 현재 | 가능하면 서버 UTC 시계 | `serverNowUtcMs` |
| 현지 달력 | 한국 시간의 날짜·시:분·초 | `calendarLocal` |
| 생존 경과 | 세계 생성 후 경과한 연속 24시간 단위 | `survivalDay` |
| 마지막 정산 | 실제 시뮬레이션을 반영한 UTC 끝점 | `simulatedUntilUtcMs` |
| 데모 시간 | 광원·날씨 연출만 보기 위한 임시 시간 | `previewTime`, 영구 저장 금지 |

- `survivalDay = 1 + floor(max(0, nowUtcMs - worldCreatedAtUtcMs) / 86,400,000)`.
- 한국 자정에 날짜가 바뀌더라도 생성 후 24시간이 지나지 않았으면 `DAY 1`이 유지될 수 있다. **달력 날짜와 생존 경과일은 별개**로 표기.
- 디바이스 날짜 조작 방지는 **서버 권위 시계 적용 시**에만 가능한 강한 보장이다. 무료·오프라인 로컬 MVP는 저장·표시 일관성을 확보하되 보안상 완전 방지라고 주장하지 않는다.
- 정식 저장 데이터에 4배속 시계를 섞지 않는다. 개발 전용 가속 시간은 별도 슬롯·플래그·별도 저장소 사용.
- 오프라인 캐릭터 상태는 최대 8시간의 생존 비용 정산(초기 제안), 8시간 초과는 보호/대기 상태로 전환한다. **달력·일수는 그대로 계속 흐른다.**
- 배경 탭 복귀, 브라우저 프로세스 재시작, 연말·윤년·DST(한국은 없음), 뒤로 간 로컬 시계, 멀티 탭 중복 정산을 반드시 테스트한다.

## 4. 핵심 플레이 루프와 입력

```text
옥상 관찰 및 날씨 감지
     ↓
필수 상태 확인 (건강/포만감/수분/체온)
     ↓
위험 징후가 있으면 예방 행동 선택
     ↓
재난 발생 → 생존자 자율 대피 → 시설/자원 피해
     ↓
복구·치료·비축 → 다음 일상
     └── 정말 자원이 부족하면 긴급 탐험
```

### 4.1 유저의 상호작용

| 입력 | 평상시 | 재난 시 |
|---|---|---|
| 드래그 | 3D 옥상 카메라 회전 | 회전하면서 피해 지점 관찰 |
| 핀치/휠 | 확대/축소 | 손상된 시설 식별 |
| 캐릭터 탭 | 상태 및 현재 행동 조회 | 대피 경로/긴급 상태 |
| 시설 탭 | 물자·내구도 확인, 수리·보강 | 배수·고정·보호 우선순위 결정 |
| 물자 메뉴 | 식량·식수·약·수리 재료 | 부족한 자원 파악 |
| 상황 메뉴 | 날씨 예보·일지 | 경보·대응 옵션·예상 위험 |

## 5. 자율 생존자 다마고치 시스템

### 5.1 관리 변수

| 변수 | 단위 | 범위/예시 | 의미 |
|---|---|---|---|
| 건강 `health` | 0~100 | 86 | 부상·질환을 포함한 전반적 회복 상태 |
| 포만감 `satiety` | 0~100 | 75 | 식사 충족도, 낮으면 피로·건강 악화 |
| 수분 `hydration` | 0~100 | 72 | 폭염·활동에 따라 감소 속도 변화 |
| 심부 체온 `coreTempC` | °C | 36.7 | 고온/저온의 위험을 게임 규칙으로 판단 |
| 활동 피로 `fatigue` | 내부 0~100 | 20 | UI에 상시 표시하지 않는 행동 우선순위 요소 |
| 질병·부상 `conditions` | 리스트 | fever, sprain | 치료·휴식 필요 여부 |

**주의:** 폭염 예시 이미지의 39°C가 외기인지 심부 체온인지 혼재해서는 안 된다. HUD에서 `기온 39°C`와 `체온 36.8°C`를 구분한다. 수치는 게임 모델로서 실제 의학적 진단이 아니다.

### 5.2 자동 행동

1. 위험 경보·시설 상태 확인; 토네이도 및 뇌우에서는 **생존 대피가 최우선**.
2. 수분과 식량이 낮으면 보유 물자에서 식사·급수.
3. 밤, 강한 피로 또는 질병일 때 수면/휴식.
4. 비가 오면 대피소, 폭염에는 그늘막, 한파에는 보온 가능한 장소로 이동.
5. 안전한 시간에는 텃밭 확인, 재료 정리, 화로 관리, 도시 관찰, 장비 수리.
6. 필수 물자가 바닥나고 해결책이 없을 때 긴급 탐험을 플레이어에게 제안.

행동 전환에는 히스테리시스와 최소 유지시간을 둬 캐릭터가 초당 식사/대피 사이를 왕복하지 않도록 한다. 이동은 3D NavMesh 또는 간단한 충돌 회피/웨이포인트 경로로 처리하되 캐릭터가 허공·난간 밖으로 나가지 않아야 한다.

### 5.3 필수 애니메이션

`idle_breathe`, `idle_look_around`, `walk`, `jog`, `drink`, `eat`, `sit`, `sleep`, `wake`, `repair`, `carry`, `shelter_enter`, `crouch_storm`, `injured_rest`. 3D 캐릭터는 하나의 정체성·비율·복장을 유지하고 애니메이션 블렌딩을 지원한다. 2D 스프라이트를 카메라 앞에 회전시키는 대체 구현은 최종 결과로 인정하지 않는다.

## 6. 재난 감독(Disaster Director)

### 6.1 공통 6단계

`CALM → OMEN → WARNING → IMPACT → AFTERMATH → RECOVERY`. 단계마다 `startedAtUtcMs`, `endsAtUtcMs`, `severity`, `position`, `direction`, `seed`, `affectedAssets`, `warningAcknowledged`를 기록한다. 난이도/시설/자원에 따라 결과가 달라지지만 동일한 시드·상태·행동 입력이면 결과는 재현 가능해야 한다.

- 전조가 충분히 인지될 것: 토네이도가 화면 한복판에 갑자기 생성되면 실패.
- 실제 피해가 있어야 함: 그래픽만 붉어지거나 흔들리고 수치가 그대로면 실패.
- 복구 결과도 3D 외형에 반영: 천막이 찢어지면 찢어진 메시, 수리하면 원상복귀.
- 긴급 상황의 사용자는 재난을 **이해하고 준비할 권한**을 가져야 한다.
- 연속 재난은 쿨다운/재난 예산으로 제어한다. 단일 1일에 극단적 재난 연속 발생 기본 금지.

### 6.2 유형별 설계

| 재난 | 전조 | 발생 | 물리·경제적 영향 | 핵심 대응 |
|---|---|---|---|---|
| 폭염 | 햇빛 강도·열기·건조한 식물 | 탈수 가속, 피로 | 식수 소모↑, 보호되지 않은 식량 훼손 가능 | 그늘, 물, 낮 활동 제한 |
| 폭우 | 이동하는 구름·빛 약화·빗방울 | 강우·물웅덩이·배수 | 물 확보 가능하지만 누수·침수·저체온 | 방수포·배수로·보관함 |
| 뇌우/낙뢰 | 먹구름·먼 천둥·빛 변화 | 3D 번개·석광·천둥 | 전력시설 손상·화재 위험 | 실내 대피·피뢰·진압 |
| 토네이도 | 먼 수평선 회오리·잔해·바람 증가 | 회오리 이동·파편 | 천막 손상·물자 유실·부상 | 고정·보강·대피 |
| 한파/눈 | 색온도 하락·서리·입김 | 눈·결빙·난방 부담 | 저체온·물 동결·생산 저하 | 보온·난방·실내 |
| 동물 침입 | 울음·움직이는 그림자 | 들개·까마귀·쥐 등 접근 | 식량 손실·부상 | 밀봉·울타리·소리로 쫓기 |

### 6.3 재난 빈도 [초기 실험값, 미확정]

초기 3일(실제 게임 시간)은 적응구간으로 강한 토네이도·치명적인 연쇄재난 제한. 이후 기본 난이도에서는 가벼운 날씨 변화가 대부분, 강한 재난은 드물게 발생하도록 시드 기반 확률과 쿨다운 적용. 확률을 `Math.random()`을 매 프레임 호출해 결정하지 않는다. 구체적 확률은 텔레메트리/사용자 테스트 이후 밸런싱 표에서 관리.

| 난이도 | 전조/대응 여유 | 피해 | 복구 난도 |
|---|---|---|---|
| 평온 | 길게 | 낮게 | 쉬움 |
| 일반 | 보통 | 보통 | 보통 |
| 극한 | 짧게 | 높게 | 어려움 |

**예측 불가능한 즉사 금지:** 심각한 사건은 선택하지 않은 플레이어에게도 최소 대피 시간이 있어야 한다. 미접속 중 8시간 상한 이후 극단적 피해는 보류하고 다음 접속 시 대피 연출/복구 가능한 상태를 보여준다.

## 7. 재난의 연쇄와 물리적 피드백

### 7.1 자원·상태·시설의 상호작용

- 폭염 → 물 수요↑ → 물탱크 수위↓ → 탈수 위험↑ → 그늘막 필요.
- 폭우 → 빗물 수집↑ / 지붕 침수 위험↑ → 배수로 막힘 가능 → 수리 재료 필요.
- 뇌우 → 순간 섬광 및 천둥 → 노출된 전기 시설 고장 → 복구 후 다시 기능.
- 강풍 → 천막 로프 텐션↑ → 내구도 낮은 시설 파손 → 방수 손실.
- 동물 → 보관함 개방/파손 시 식량 손실 → 특정 조건에만 긴급 탐험 발생.

시각/물리는 동기화하되 게임 로직을 모든 물방울의 CPU 물리로 계산하지 않는다. 파손·보관·자원 상태는 결정론적인 데이터 모델이 권위이며 시각 효과는 그 결과를 보여준다.

### 7.2 시설 기본 데이터

| 시설 | 필수 상태 | 단순히 예쁘기만 한 시설 금지 |
|---|---|---|
| 텐트/대피소 | `integrity`, `waterproof`, `windResistance`, `occupied` | 비와 강풍을 막고 안으로 대피 |
| 물탱크 | `liters`, `capacity`, `filterHealth`, `integrity` | 정수 전 빗물과 식수 구분 |
| 식량 보관함 | `stock`, `sealed`, `integrity` | 동물과 습기에 대한 방어 |
| 그늘막 | `shadeCoverage`, `windResistance`, `integrity` | 체온 및 풍압 영향 |
| 배수로 | `clogLevel`, `drainRate`, `integrity` | 물웅덩이 수위 변화 |
| 울타리 | `integrity`, `barrierCoverage` | 동물 침입 확률 저하 |
| 피뢰/소화 | `grounded`, `charges`, `integrity` | 낙뢰 피해 완화/화재 진압 |

## 8. 경제·소모·회복 — 노가다보다 사전 대비

핵심 자원은 **식량, 식수, 의약품, 수리 재료** 네 범주다. 내부 제작 재료(천, 목재, 고철 등)는 필요한 경우만 하위 재료로 사용하고 상시 메뉴에 가득 펼치지 않는다.

- 시설의 상한 저장량과 자동 소비를 일관된 시간 단위로 관리.
- 식수는 강우가 올 때 수집할 수 있지만, 정수되지 않은 물을 마시면 불이익이 있을 수 있다는 설계는 난이도에 맞게 낮은 비중으로 제한.
- 복구 비용은 최대한 예측 가능하게, 사전에 물자 준비가 보상되도록 설계.
- 플레이어가 1주일에 한 번 정도만 접속하는 경우에도 장기 방치가 일괄 사망으로 이어지지 않음.
- 경제 수치/쿨다운/확률은 코드 상수가 아니라 데이터 테이블(JSON/TS config)로 관리해 테스트 조정.

## 9. 드문 긴급 탐험

상시 보상 파밍이나 지도 탐색은 불허. 옥상 아래로 내려가는 상황은 **가장 중요한 자원 결핍**이어야 한다. 조건 예시:

1. 남은 식량으로 일상 유지 불가능 → 버려진 상점/아파트 창고에서 보급 식량 찾기.
2. 질병/부상이며 의약품 0 → 폐약국 방문.
3. 대피소 내구도 위험이며 수리 재료 0 → 아래층 철물실 탐색.

진행: `긴급 필요 감지 → 떠날지 결정 → 경로·위험·예상 시간 표시 → 짧은 사건 선택 1~3회 → 복귀 → 결과 저장`. 자동으로 수십 번 반복 파견할 수 없도록 하되 영구적인 진행 불능도 막아야 한다. 비탐험형 대안(교환·재활용·정비)을 일부 준비한다.

## 10. 난이도·생존 실패·윤리

- 초보자의 첫 하루에 큰 불이익 금지.
- 위험은 강도와 누적 노출에 비례하며, 한 번의 운 나쁜 추첨으로 수개월짜리 저장이 사라지지 않음.
- 고난도에서 사망을 허용한다면 별도의 명시적 '하드코어 슬롯'으로만 제공하는 것이 합리적. 기본 모드는 중상·정비 실패·복구 부담으로 긴장감을 제공.
- 캐릭터의 질병은 게임 내 추상 상태이며 의료 조언을 제공하지 않는다.

## 11. 화면과 정보 구조

**3D 화면을 가장 먼저 본다.** 상단 `DAY / 현지시각 / 기상`, 우측 재난 상태 아이콘, 하단 4개 핵심 상태 및 `[물자] [시설] [상황]`. 긴급할 때만 1개 경고 레이어와 선택형 버튼. 설정/라디오/품질은 접힌 보조 메뉴로 이동.

| 위치 | 평온 | 경보 |
|---|---|---|
| 상단 | DAY 12 · 07:40 · 흐림 | DAY 12 · 18:55 · 토네이도 접근 |
| 중앙 | 대부분 3D 월드 | 월드+가독성 있는 경고 배너 |
| 하단 | 건강 / 포만감 / 수분 / 체온 | 대피 / 시설 고정 / 상황 확인 |
| 확장 패널 | 물자/시설/일지 | 재난 설명/대응 선택 |

입력 범위는 터치 타깃 44×44 CSS px 이상, 노치 안전영역 적용, 횡회전·확대·터치 선택 충돌 방지.

## 12. 주요 골든 패스 플레이 시나리오

### A. 자연스러운 평온→밤

07:00 생존자가 기상·물 마심 → 12:00 천막 그림자 짧아짐 → 18:00 긴 그림자와 도시 주황빛 → 21:00 모닥불 주변이 따뜻하게 빛남 → 수면 → 다음 날. **광원·그림자·하늘이 시간 경계에서 점프하지 않을 것.**

### B. 폭염과 대비

맑음 → 기온 상승/바람 약화 → 생존자가 외투 소매를 걷고 그늘로 이동 → 물 소비 증가 → 물탱크 수위 감소 → 보충/그늘막 보강을 선택하면 위험 완화.

### C. 폭우와 복구

먼 구름 등장 → 맑은 그림자 약화 → 빗방울 증가 → 젖은 천막·바닥·난간 → 배수 흐름 시작 → 배수로 막히면 수위 증가 → 수리하면 물 빠짐 → 재난 뒤 흔적 남음.

### D. 토네이도와 선택

먼지와 바람 소리 → 멀리 움직이는 회오리 → 시설 흔들림 → 사용자에게 `생존자 대피 / 물자 고정` 중 선택 → 실제 피해 → 파손된 천막과 유실 물자 → 복구. **원경 회오리와 시설 피해 타이밍이 하나의 같은 사건 데이터를 사용해야 한다.**

### E. 약품 고갈 긴급 탐험

부상 → 약 사용 → 의약품 0 → 폐약국 탐험 필요 표시 → 아래층으로 내려가는 연출 → 위험한 출입구 선택 → 약 발견·복귀·치료 → 안전한 옥상으로 귀환.

## 13. 콘텐츠 데이터 예시 (계약 초안)

```json
{
  "scenarioId": "storm_intro_001",
  "trigger": {"hazard": "tornado", "phase": "WARNING", "minSurvivalDay": 3},
  "choices": [
    {"id": "evacuate", "label": "먼저 대피", "risk": "resource_loss", "priority": "character_safety"},
    {"id": "secure", "label": "물자 고정 후 대피", "risk": "minor_injury", "priority": "inventory_safety"}
  ],
  "resolvable": true,
  "visualFeedbackRequired": true
}
```

**주의:** 위 JSON은 스토리 의도 예시이며 실제 확률과 피해 수치가 확정되었다는 뜻은 아니다. 선택의 위험은 과장·은폐하지 말고 HUD로 미리 표현한다.

## 14. 수치 설계와 밸런스 프로토콜

| 파라미터 | 초기값 또는 정책 | 확정 조건 |
|---|---|---|
| 시간 배율 | 1:1 | 확정(사용자 요구) |
| 시뮬레이션 정산 스텝 | 1~5분 중 테스트 | 오프라인 재현 및 비용 측정 |
| 오프라인 소모 상한 | 8시간 [제안] | 24h/72h/30d 복귀 UX 테스트 |
| 첫 재난 튜토리얼 | 약한 폭우 [제안] | 핵심 피드백 학습 확인 |
| 토네이도 빈도 | 초기에는 드물게 | 이탈/성공률 테스트 |
| 상태 소비율 | 미확정 | 생존 부담 테스트 |
| 시설 비용 | 미확정 | 재난 후 회복 시간 테스트 |

수치가 정해지지 않은 것은 무작정 하드코딩하지 않는다. Codex는 초기 config와 단위 테스트를 제공하고 `balance-notes.md`에 가정 근거를 명시한다.

## 15. 상용화 기준의 성공 지표 [제안]

- D1 / D7 / D30 retention(실측 시), 일일 자발 접속 빈도, 짧은 세션 종료율.
- 카메라 회전 사용률, 날씨 전조 관찰 후 대응율, 생존자 자동행동 관찰 체류.
- 재난 대응 성공/실패, 복구에 소요된 시간, 긴급 탐험 발생 빈도.
- 생존자 상태 악화와 이탈 사이의 상관, 장기 미접속 뒤 복귀율.
- 성능: 3D 씬 진입 성공률, 모바일 프레임 안정성, 메모리 및 발열.

현재는 상용 사용자 데이터가 없으므로 목표 숫자나 실제 성과를 임의로 기재하지 않는다.

## 17. 이 문서의 DoD (Definition of Done)

- 실제 3D 카메라가 옥상을 360° 돌아도 천막 뒷면·물탱크 배관·도시 원근이 실재함.
- 날짜/시간은 새로고침·앱전환·자정·윤년·날짜 이동에서 정합함.
- 날씨는 멀리서 점진적으로 다가오고 시설과 생존자가 실제로 반응함.
- 생존자 1명이 최소 `idle, walk, eat, drink, sleep, shelter` 애니메이션을 실제 메시에서 구동함.
- 피해 흔적은 복구 전까지 남음. 자원 변화와 시각 연출 불일치가 없어야 함.
- 모바일 Safari·Chrome에서 부팅/카메라/UI/재난 테스트 수행 및 증적 저장.
- 게임의 외형은 참조 고품질 시안을 목표로 하지만 **참조 PNG를 3D 모델로 오인하거나 단지 화면에 붙이는 것으로 완료 선언하지 않음**.
