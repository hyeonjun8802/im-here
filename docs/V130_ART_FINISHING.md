# AFTERDAY v1.3 — Premium World-Space Art Finishing

2026-10-31 · Three.js 게임 **실제 소스 수정** / 원본 콘셉트 고정

## 0. 성과와 한계

이 버전은 v1.2의 기본 구조·시간·생존·날씨·도시 배치·생활 행동을 유지하면서 렌더링에 실제 연결된 오브젝트를 보강한다. 신규 참고 이미지나 합성 스크린샷을 게임 완성으로 취급하지 않는다. 수정 내용은 아래 파일에 구현되었다.

- `src/premiumEnvironmentV130.js`: 지붕과 건물 외벽의 식생·재료·빗물·모닥불 파티클
- `src/premiumArtPlanV130.js`: 모바일/데스크톱 리소스 예산 및 단일 옥상 불변값
- `src/survivorFinishingV130.js`: 기존 움직이는 캐릭터 관절에 고정되는 의상·장비·후드
- `src/cinematicPostV130.js`: 데스크톱에서 고휘도 랜턴/모닥불만 강조하는 약한 bloom
- `src/world.js`: 위 구성요소의 생성·매 프레임 업데이트·화질 조절·해제 연결
- `tests/premiumArtV130.test.mjs`: 회귀 테스트 및 씬 불변성 정적 검사

**최종 그래픽 수준은 실제 실행된 GPU 프레임과 레퍼런스 이미지를 동일 카메라에서 비교하기 전에는 판정 불가.** 이 패키지는 전문 3D 아티스트가 제작한 수작업 캐릭터 모델이나 SSR·레이 트레이싱 등 상용 최종 아트 완성판이 아니다.

## 1. 3D 식생 — 큰 실루엣과 원근

### 1.1 영웅 건물 외벽 덩굴

- 주인공 건물 난간에 붙어 아래로 늘어지는 **54개(모바일 32개) 실제 3D 줄기**, 길이가 모두 다르고 원래 영웅 건물에 부착된다.
- 줄기는 `THREE.TubeGeometry`, 잎은 전·후면이 존재하는 굽은 3D 메시를 `THREE.InstancedMesh`로 배치한다. 잎은 실제 3D 카메라 회전에 맞춰 측면과 광원 반응을 보인다.
- 전체 덩굴과 옥상 식물 합계 2,200잎(모바일 930잎), 개별 게임오브젝트가 아닌 배치 렌더링. 단일 색 플라스틱처럼 보이지 않도록 각 잎 색상·방향·크기 변형을 가진다.
- 잎 끝은 GPU vertex shader 바람 변위, 옥상 관목 26곳(모바일 14곳)의 나뭇가지에는 보조 운동을 사용한다.

### 1.2 생존 옥상 나무 1그루

- 주인공 옥상 좌측 후면(-18,-14)에 높이가 있는 나무 1그루를 3D 제작. 돌화분, 굽은 줄기, 15개 분지, 입체 잎사귀를 포함한다.
- 데스크톱 나뭇잎 540개 / 모바일 260개 인스턴싱. 데스크톱에서만 나무 잎 그림자를 생성한다.
- 나무는 게임 옥상 하나에만 추가되며 도시 쪽에 또 다른 플레이 옥상, 연결된 길, 활동 장소를 만들지 않는다.

### 1.3 마모된 구조 디테일

- 기존 바닥을 덮는 거대한 판을 추가하지 않고 **옥상 가장자리**에만 58개의 얇은 금속 수선판, 285개(모바일 115개)의 부스러기를 인스턴싱한다.
- 건물 외벽에 4개의 실제 곡선 배수관과 연결부를 추가한다. 작동하지 않는 시각적 배경이 아니라 강우 때 배수/물줄기 연출과 시각적으로 연결한다.
- 기존 GLB 천막·물탱크·보관함과 활동 장소는 삭제하거나 가리지 않는다.

## 2. 날씨와 함께 변하는 오브젝트

- 3D 배수 흐름 20개(모바일 12개): `weather.rain > 0.09`에서만 노출. 알파 및 바람 기반 작은 흔들림.
- 물줄기는 기존 처마에서 아래로 떨어지는 간단한 메시다. 실제 SPH 유체 물리나 광선 추적된 수면이 아니다.
- 모닥불에서 발생하는 앰버색 불씨 64개(모바일 28개): 각기 다른 상승 속도·위상·회전, 강우량이 증가하면 감소. 기존 게임의 모닥불/온기 관련 생존 규칙은 변경하지 않는다.
- `src/advancedWeather.js`/`src/cinematicWeatherVfx.js`/`src/cityAtmosphere.js`/`src/solar.js` 로직은 기존대로다.

## 3. 생존자 실루엣·재질·동작 유지

`src/survivorFinishingV130.js`는 v1.2 인물의 `survivorTorso`, `survivorHead`, `survivorHands`를 그대로 사용한다.

- 어깨를 따라 늘어지는 방수 천 패널과 수선/봉제선, 옷깃, 등쪽 가방 고정 스트랩 및 버클.
- 손목 움직임과 함께 이동하는 작업 장갑 세부 구조.
- 실물 형태의 나침반 프레임, 침수·마모된 천과 가죽·금속 차이.
- 고개 회전과 함께 움직이는 후드 테두리, 상체를 따라 흔들리는 스카프 끝단.
- 별도 가짜 캐릭터나 얼굴 합성 이미지를 게임 3D 모델로 대체하지 않는다.
- 기타 연주, 착석, 식사, 무전, 걷기, 대피는 **기존 v1.1 행동 엔진**이 담당한다.

**한계:** 여전히 절차적 관절형 메시이므로 부드러운 고급 스켈레탈 스키닝, 자연스러운 표정, 손가락 IK, 모션 캡처 수준으로 평가해서는 안 된다.

## 4. 게임 카메라·조명 품질

`src/cinematicPostV130.js`는 THREE 공식 애드온 `EffectComposer`, `RenderPass`, `UnrealBloomPass`, `OutputPass`를 사용한다.

- 데스크톱 자동/높음 품질 시 **threshold=1.10 / strength=0.23**의 절제된 bloom. 매우 밝은 모닥불·랜턴의 눈부심만 부드럽게 확산시키는 용도.
- 모바일에서는 bloom 기본 비활성화. 저화질 모드에서는 데스크톱에서도 비활성화. 기본 WebGLRenderer로 즉시 되돌아갈 수 있다.
- RGB 색감 변화, 원경 안개, 태양 고도, 조명 세기는 기존 값을 유지. 서바이버 생활 UI·날씨 메뉴 조작도 유지.
- 후처리는 SSR 또는 볼류메트릭 레이마칭이 아니며, 실브라우저 GPU 성능 실측이 필요하다.

## 5. 콘셉트 불변 규칙

1. 유일한 생활 옥상 1개와 단독 생존자 1명.
2. 실제 서울의 폐허 원경 건물은 3개 물리적 거리 구역을 사용하고 좌표가 날씨에 따라 변하지 않는다.
3. 따뜻한 캠프 조명 vs 차가운 폐허 도시, 실용적 재활용 자재, 복구 가능한 시설.
4. 고층 건물을 주인공 옥상에 붙이지 않는다. 주변 연결된 옥상이나 추가 캠프를 만들지 않는다.
5. 실제 생존 날짜와 시연 날씨/시각을 혼합하지 않는다.
6. 기존 GitHub 원본 GLB의 허용 목록과 라이선스를 보존한다.

## 6. 검수 순서

1. `npm install` / `npm run download:assets` / `npm test` / `npm run build`
2. `npm run dev` 후 `http://localhost:5173/?showcase=1`
3. PC Chromium과 iPhone Safari에서 *같은 카메라*로: 옥상 전체, 생존자 확대, 폭우, 일몰, 야간 낙뢰, 식물 바람 반응 캡처.
4. 특히 식물 잎의 alpha clipping, shader 컴파일, 과도한 bloom, 3D 배수 표면 반짝임, 나무가 천막을 가리는지, 지붕 중복 문제가 재발했는지 검토.
5. `docs/visual-reference/rooftop_target.png` 및 `docs/visual-reference/v090_target_*.png`와 실제 캡처를 비교.
6. 태블릿/모바일에서 30FPS 목표(성능 실측 전 보장할 수 없음). GPU 메모리/텍스처 압축/셰이더 처리 시간을 구분해 측정.
7. 실제 기준에 도달하지 못하면 다음 단계는 절차적 얼굴·의상 대신 **전문 리깅 캐릭터 GLB, 텍스처 아트, 스켈레탈 IK**를 별도 자산 파이프라인에서 제작해야 한다.
