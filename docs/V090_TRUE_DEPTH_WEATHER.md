# AFTERDAY v0.9.0 — 3D 도시 원근·거리별 안개·날씨·설원 전면 수정

## 0. 사용자 의도 해석 / 불변 조건

단 하나의 생존 옥상은 플레이 장면의 유일한 전경 지붕이다. 그러나 **그 옥상이 허공에 단절된 도시처럼 보여서도 안 된다**. 옥상 건물과 연결되지 않은 폐허 서울 건물들이 3D 공간의 가까운 층, 중간 층, 먼 층에 각각 존재해야 하며, 카메라를 움직일 때 위치 관계가 달라지는 **실제 시차(parallax)**가 나야 한다.

사용자가 원하는 안개는 단순 회색 오버레이가 아니다. 가까운 빌딩은 창문·파손·수목이 일부 읽히고, 중간 빌딩은 발밑부터 안개에 잠기며, 먼 빌딩은 낮은 콘트라스트의 실루엣으로 사라지는 **깊이별/높이별 안개**다. 비·눈·낙뢰·토네이도가 오더라도 **동일한 3D 건물의 좌표가 유지**되어야 한다.

## 1. 도시 3D 배치 — 실제 좌표

기존 v0.8에는 49개의 도시 건물이 245~445 단위 사이에 무작위 배치되어 층별 깊이를 읽기 어려웠다. 새 `src/spatialLayout.js`는 바뀌지 않는 시드 기반 물리 좌표와 세 개의 실제 거리 링을 만든다.

| 구분 | 데스크톱 / 모바일 건물 수 | 옥상 중심으로부터 반경 (월드 단위) | 시각적 역할 |
|---|---:|---:|---|
| 플레이어의 옥상 | 1 / 1 | 0~23 | 천막·화덕·물탱크·식물·생존자 |
| 비어 있는 구역 | 건물 없음 | 23~140 | 고립된 한 생존 옥상임을 보장 |
| **근경 도시** | **28 / 18** | **166~295** | 창문·구조·식생·부분 안개가 보이는 건물 |
| **중경 도시** | **52 / 28** | **315~535** | 서로 다른 높이와 윤곽의 건물. 하부 안개 띠 |
| **원경 도시** | **80 / 42** | **570~875** | 깊은 거리 안개에 묻힌 구조물 실루엣 |
| 실제 3D 산능선 | 1개 이어진 지형 | 약 1000~1100 | 먼 서울의 지형 깊이 |
| 하늘 텍스처 | 구름만 | 1260 이상 | 건물과 무관한 최원경 하늘 질감 |

모든 건물에는 `id, tier, x, z, radius, height, width, rotation, modelIndex`가 부여된다. 날씨는 이 배열을 다시 생성하지 않는다. 카메라 줌 상한은 124유닛으로 제한해 근경 건물과 관찰자가 충돌하지 않도록 했다.

## 2. 거리 및 고도 안개

- 기초 `THREE.FogExp2`: `density = 0.00128 + mist*0.00148` (mist 0~1).
- 순수 거리 감쇠 참고식: `1 - exp(-pow(distance*density,2))`. 가까운 물체가 먼저 통째로 숨지 않도록 수치를 정했다.
- `src/cityAtmosphere.js`: 높이와 거리를 모두 가진 반투명 구름 뱅크 78개(모바일 38개). 각 뱅크는 근/중/원경 건물 사이에 독립된 월드 좌표를 갖고, 바람에 조금씩 이동한다.
- 빗줄기 띠는 원거리 빌딩 주변에 별도 3D 평면으로 배치된다. 폭우에서는 먼 빌딩의 실루엣을 잔잔하게 가리고, 맑은 날에는 투명해진다.
- 의도된 근경 보존: 시야 근처 건물의 꼭대기, 창문 구조와 일부 자연 재생 흔적은 회색 안개에 덮이지 않고 읽히도록 설정한다.

**정직한 한계:** 이 구현은 거리 안개와 레이어 안개 텍스처를 조합한 근사적 깊이 연출이지 물리 기반 3차원 레이마칭 볼류메트릭 안개가 아니다.

## 3. 동일한 도시를 유지하는 날씨 변형

기존 `skyline_dusk/noon/storm/night.jpg`는 건물 모습이 중복·변형된 렌더 이미지여서, 날씨마다 시티스케이프의 건물 배치가 바뀌어 보일 수 있었다. 새 `scripts/extract_sky_only.py`는 기존 소스 이미지에서 **상단 구름 픽셀만** 분리했다. `public/assets/materials/sky_only/sky_*.jpg`는 도시 건물 픽셀을 잘라낸 구름과 대기 그라데이션이다.

- `createAtmosphericBackdrops()`는 4개 날씨별 하늘 질감을 **서서히 교차 페이드**한다.
- 배경 3D 건물, 실제 폐허 건물의 위치, 언덕·통신탑 위치는 고정된다.
- 실제 태양광 그림자, 환경광, 원경 안개 색, 빌딩 창문의 소량 점등은 날씨와 시간에 반응한다.
- 온도·식수·식량·재난 상태와 시뮬레이션 저장/일수 산정은 기존 `simulation.js`를 유지한다.

## 4. 캠프 날씨 효과

| 상태 | 이번에 구현/유지한 실제 코드 |
|---|---|
| 흐린 아침·황혼 | 3D 원근 도시 + 구름만 있는 파노라마 + 계절별 태양고도 + 은은한 근경 안개 |
| 폭염 | 높은 태양고도와 강한 방향광, 가시거리 감소·황토색 대기 톤 |
| 폭우 | 옥상 빗줄기, 젖은 2K 콘크리트/PBR 클리어코트, 불규칙한 웅덩이, 세계 좌표에 배치한 작은 광택/불빛 반사, 빗물 배수, 원거리 3D 강우 띠 |
| 낙뢰 | 구름 하늘 급변, 분기형 번개·번쩍이는 씬 조명, 젖은 바닥 반사 강조 |
| 토네이도 | 먼 시가지의 실제 3D 회오리, 파편 이동, 근/중경의 바람·안개 이동, 접근 경보·대피 규칙 |
| 눈 | 3D 눈 입자 + 옥상 표면·난간 주변에 쌓이는 3D 적설 덩어리, 차가운 하늘 톤 |

반사는 특정 위치에 있는 불빛의 글린트와 물기 마스크를 계산한 **뷰 의존 셰이더 근사**다. 정확한 장면 반사/SSR/레이 트레이싱은 구현하지 않았다. 눈은 삼각형 메시 인스턴스로 바닥 표면에 쌓이며, 실제 유체/결정 성장 시뮬레이션은 아니다.

## 5. 실제 서울의 계절성 태양광

`src/solar.js`는 서울 위도 37.5665°N, 경도 126.978°E, KST(UTC+9)를 사용해 NOAA 근사식에 따른 태양 고도·방위를 계산한다. 계절별 낮 길이의 차이를 반영하며 태양 방향·실제 세계 그림자에 사용한다. 시연 패널의 시간 변경은 화면 광원만 변경하고 저장된 생존 시각과 일수는 건드리지 않는다. 천문 관측 수준 정밀도는 목표가 아니다.

## 6. 3D 에셋/모델 사용

기존 전용 3D GLB 3종(천막·물탱크·보관함)은 그대로 사용한다. 근경/중경 3D 폐허 건물은 기본적으로 원본 GitHub의 유효한 서울형 건물 GLB를 시도한다. 리소스가 없거나 너무 작으면 `src/world.js::makeRuinFallback()`의 창문·파손·식생 디테일이 있는 **3D 모델**을 대신 사용한다. 후면·측면 및 실재 좌표가 있으므로 카메라를 돌려도 납작한 도시 배경 이미지는 아니다. 원경은 경량 3D 모델을 쓴다.

새 건물 폴백용 재질 `facade_0..3.jpg`와 야간 창문 emissive 지도 4장을 포함한다. 낮·밤에 같은 건물 모델을 사용한다. 원본 GitHub GLB 바이너리 83종은 네트워크에서 별도로 다운로드해야 한다.

## 7. 게임 실행·검증 기준

- `npm test`: 건물 수/좌표/반경/불변성, 근경·원경 안개 단조성, 날씨 보간, 실제 서울 태양, 기존 생존자/저장/날짜 시스템.
- `python scripts/audit_hero_glb.py`: 실제 GLB 헤더, 메시/UV/PBR 구조.
- `npm run build` 및 Chrome/WebGL2 화면, iOS Safari 화면과 FPS 검증은 **현 환경에서 미완료**. Node 테스트만으로 상용 품질 또는 스크린샷과의 일치도를 인정하면 안 된다.

실제 검수 순서: (1) 맑은 황혼 구도, (2) 카메라 360°에서 3D 시차 확인, (3) 폭우 시 근/중/원경 안개와 비·반사 확인, (4) 낙뢰·토네이도, (5) 눈 쌓임, (6) 최저 모바일 FPS, (7) 사용자 콘셉트 이미지와 직접 비교.
